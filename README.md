# Fishbone Builder (Ishikawa diagram) — React + iPad

A small app for building cause-and-effect (Ishikawa / fishbone) diagrams on an iPad.
It is also a **teaching codebase**: every file is commented to explain what the code
does and why.

**What it does**

- Type the problem (the fish "head") and fill in causes on each category branch
- Starts with the classic six categories: Machine, Method, Material, People, Measurement, Environment
- **Add up to 3 extra branches** (9 total); rename or remove any of them
- Up to 7 causes per branch
- **Clear diagram** button (with an "are you sure?" box) resets everything
- Tap anything on the diagram to jump to its text field; press Return to add the next cause
- Auto-saves on the device and works offline

## Get it running on an iPad

There are two routes. Start with Route A; it needs no Mac.

### Route A — Installed web app (fastest, no Mac needed)

1. Build: `npm install && npm run build` (a ready-made `dist/` folder is also included in the zip).
2. Put the contents of `dist/` on any web server that uses **HTTPS** (your intranet, SharePoint-hosted
   static site, Azure/AWS static hosting, GitHub Pages, etc.).
3. On the iPad, open the address in **Safari** → **Share** → **Add to Home Screen**.
4. It now launches full-screen from its own icon, and works offline after the first load.

### Route B — Native iPad app (Capacitor wrapper)

Needs a **Mac with Xcode** and an Apple ID (a free Apple ID installs to your own iPad for 7 days; an
Apple Developer Program membership is needed for TestFlight or company distribution).

```bash
npm install
npm run icons            # (optional) regenerate icons with Python
npm run ios:add          # builds the web app, creates the ios/ Xcode project (first time only)
npx @capacitor/assets generate --ios    # (optional) app icon from assets/icon-only.png
npm run ios:open         # opens Xcode
```

In Xcode: select the **App** target → *Signing & Capabilities* → pick your team → choose your iPad
(or a simulator) at the top → press **Run ▶**. After changing code later, run `npm run ios:sync`
and Run again.

> Note: the native wrapper step was **not** run in the environment where this was built (it requires
> macOS and Xcode). The web app itself was built, unit-tested, and checked in a browser at iPad sizes.
> Capacitor's generated iOS project may ask you to update settings on first open — accept Xcode's
> recommendations.

### Developing on any computer

```bash
npm install
npm run dev      # live-reloading dev server (open the printed address; use --host to reach it from the iPad on the same Wi-Fi)
npm test         # 8 automated tests of the rules and layout
```

## Tour of the code (read in this order)

| File | What it teaches |
|---|---|
| `src/state.js` | The **data model** and a **reducer**: all the rules (limits, add/remove, clear) in one pure function |
| `src/layout.js` | Pure **geometry**: turns branches + causes into x/y coordinates (no React) |
| `src/components/FishboneDiagram.jsx` | Drawing with **SVG in React**; turning data into shapes; touch targets |
| `src/components/EditorPanel.jsx` | **Controlled inputs**, `useEffect`, `useRef` (focus management), keyboard handling |
| `src/components/ConfirmDialog.jsx` | A modal dialog, event propagation, effect cleanup |
| `src/App.jsx` | **State ownership**, `useReducer`, `useMemo`, passing props and callbacks down |
| `src/storage.js` | Saving to the device and **validating** loaded data |
| `src/styles.css` | Responsive layout, iPad touch sizing, CSS variables |
| `tools/layout.test.mjs` | **Automated tests** with Node's built-in test runner |
| `tools/make_icons.py` | **Python** (Pillow) script that generates the app icons |
| `public/sw.js`, `public/manifest.webmanifest` | Offline support and "installable app" settings (JavaScript + JSON) |
| `capacitor.config.json` | Settings for the native iOS wrapper |

### The core React ideas in this app

1. **State** — one object describes the whole diagram (`state.js`). The screen is just a picture of it.
2. **Actions** — buttons don't change data directly; they `dispatch({ type: 'ADD_CAUSE', ... })`.
3. **Components** — small reusable pieces (`BranchCard`, `FishboneDiagram`) that receive **props**.
4. **Effects** — code that runs *because* something changed: auto-saving, moving the cursor.
5. **One-way data flow** — data goes down as props; events go up as callbacks.

### Languages used, and why

- **JavaScript / JSX (React)** — the app itself
- **CSS** — look and iPad touch behaviour
- **HTML** — the single page shell (`index.html`) with iPad home-screen settings
- **JSON** — app manifest, Capacitor and npm configuration
- **Python** — icon generation (`tools/make_icons.py`), a one-off build chore
- **Swift/Xcode** — only generated by Capacitor in Route B; you don't write any

## Easy changes to try (good exercises)

| Goal | Where |
|---|---|
| Use the "8 P's" or custom default categories | `DEFAULT_CATEGORIES` in `src/state.js` (adjust `PALETTE` if you add more than 9) |
| Allow more or fewer extra branches | `MAX_EXTRA_BRANCHES` in `src/state.js` |
| Allow more causes per branch | `MAX_CAUSES` in `src/state.js` (layout spacing may get tight) |
| Change colours | `PALETTE` in `src/state.js`; page colours at the top of `src/styles.css` |
| Rename the app | `index.html`, `manifest.webmanifest`, `capacitor.config.json` |
| Add sub-causes ("5 Whys") | Extend each cause with a `children` list in `state.js`, then draw them in `layout.js` |
| Export as image/PDF | Serialize the `<svg>` to a canvas; on native iOS pair it with Capacitor's Share/Filesystem plugins |

## Known limits

- Long cause text is shortened with "…" **on the diagram only**; the full text is always in the editor.
- No export/share yet (see the table above); the diagram is saved on the device it was created on.
- One diagram at a time (a "My diagrams" list would be a good next lesson: store an array of states).
- Data lives in the browser/WebView's local storage. Clearing website data in Safari or deleting the app erases it.
